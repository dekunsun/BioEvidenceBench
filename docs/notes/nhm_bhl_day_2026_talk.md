# BHL Day 2026 的 NHM 报告：口头讲解补充了什么（学习笔记）

> 报告：Ben Hartley、Qianqian Hiris Gu、Vince Smith（伦敦自然历史博物馆），*BHL & the Planetary Knowledge Base*，
> BHL Day 2026。录像：<https://www.youtube.com/watch?v=xTMxsl5v7bY>。
> 来源：15 页幻灯片（PDF），以及 Gloria 整理的逐页中英文讲稿（由录像转写后编辑，不是逐字稿）。
> **本笔记没有直接看录像**，口头内容全部来自那份整理稿；整理稿里的语音识别错误可能还有残留。

## 1. 口头讲解比幻灯片多出来的信息

| 主题 | 幻灯片上写的 | 口头补充的 |
|---|---|---|
| 性状抽取的规模 | 706,852 个性状词、81 种性状、106,433 段描述、59,360 种（342,625 种已接受被子植物的 17%） | 没找到描述的物种，部分原因是语料只限英文文献；"仅用 BHL 文献就建成了同类中最大的开放植物性状数据集之一" |
| 性状抽取的代价 | 两步流程图（找描述 → 抽性状） | "背后是大量定制工程"；"我们不可能为每个生物多样性问题都建一条定制流水线"，所以需要通用的 AI 基础设施。这是他们转向 LLM 的理由 |
| 为什么转向 LLM | "Transformers → LLMs → AI at Scale；But: Costs; Errors" | 专用模型对特定任务很准，但要多语言、要处理整个 BHL 时很难适配；LLM 更灵活，但带来算力成本、幻觉，以及下游数据处理和验证的需要。"问题不再是能不能用 LLM，而是怎么搭建让它可靠、可规模化的基础设施" |
| 原型的范围 | 2 种期刊（1865–2017），35,721 页，与 AWS 原型团队合作，4 周 | "已经可以运行，不只是概念" |
| OCR | "OCR Accuracy: 99.57%" | 是**词级**准确率，"在我们测试的 BHL 材料上"；先用现代 OCR 重新识别，因为 BHL 现有 OCR 有一部分是旧技术做的 |
| 实体抽取 | Taxa ✔、People ✔、Localities ✔、Institutions、…… etc；"Taxon Extraction: F1 96.15%" | 识别后的文字交给一个云端 LLM 抽实体，口头列举的是"taxa, habitats, localities, institutions"；之后做标准化，再建知识图谱 |
| 文章标题页识别 | 无目录卷 98.76%，有目录卷接近 100% | 用来把一卷拆成单篇文章，给每篇配上出版记录、引用，将来可能配 DOI；"这些实验也有评估统计" |
| 知识图谱的作用 | "PKB enables linking, standardisation, and data quality control" | 把 LLM 的输出"接地"到图谱上，"在生成时对照结构化知识检查"，以减少没有依据的陈述；多语言检索（包括拉丁文）、以图搜图并识别图中的类群 |
| 下一步 | 重新 OCR 整个 BHL；文章切分和实体抽取做成生产模型；用 BHL 子集做 InvenioRDM 原型 | 有一年的全职工程师、Hiris 的投入、5 万英镑的云计算和 Mistral OCR 预算。**当天上午讨论后计划有调整**：不做 InvenioRDM 原型，改做一个查询知识图谱的原型检索界面，与现有 BHL 界面并行 |

## 2. 幻灯片、讲稿和我们复现结果之间对不上的地方

- **工具名。** 讲稿里写的是 "ADAPT"，公开仓库叫 **ADEPT**（`NaturalHistoryMuseum/ADEPT`）。应当是语音识别的错。
- **"Harriet and I"。** 讲稿里 Ben 说这个项目是"Harriet 和我"做了五年；幻灯片写的是 "Lead: Dr Neil Brummit"，引用的论文第一作者是 T. Harris。这个名字可能是转写错误，**未核实**。
- **"训练了 transformer 模型来识别植物描述"。** 幻灯片第 6 页写的是 "bag-of-words threshold classifier"，我们复现时看到的描述分类器也是 spaCy 的词袋文本分类器；transformer 用在后面的数值识别和句法分析里（见 `adept_repro/NOTES.md`）。口头说法比代码粗略。
- **实体类型。** 口头说的是 habitats，幻灯片第 9 页打勾的是 Taxa、People、Localities。界面截图（第 10 页）里四种高亮都有：TAXON、PERSON、LOCALITY，以及 HABITAT。其中 HABITAT 高亮的是**一整句**（"Its natural habitat is quite far from…"），粒度和其他实体不同。筛选栏里还有 Country。所以"他们抽哪些实体"的准确说法是：一个可扩展的集合，演示里出现了学名、人、地点、机构、生境、国家。
- **96.15% 只是学名。** 幻灯片写的是 "Taxon Extraction: F1 96.15%"，不是所有实体的综合分数。

## 3. 报告里没有给出依据的地方

这些不是批评，而是我们自己做评估时要补上的东西，也可以作为向 Hiris 请教的问题。

1. **96.15% 是怎么算的**：测试集多大、来自哪两种期刊的哪些页、金标准谁标的、匹配规则是严格边界还是重叠、是不是开发集。口头完全没提。
2. **99.57% 的 OCR 词级准确率**对照的是什么参照文本，样本怎么抽的。
3. **人、地点、机构**有没有分数。幻灯片上这三项只有 Taxa、People、Localities 打了勾，没有数字。
4. **"接地到图谱以减少幻觉"**有没有量化：加不加图谱，没有依据的输出各占多少。
5. **标准化和关联**（把抽到的名字对到图谱里的实体）的准确率。这是他们流程的第三步，报告里没有任何数字。
6. **OCR 质量对下游抽取的影响**：他们先换了 OCR 再抽取，没有展示同一批页面上旧 OCR 和新 OCR 的抽取对比。

## 4. 对 BioEvidenceBench 的意义

- **我们的问题正好落在他们没有展示的那一段。** 他们的流程是 OCR → 实体 → 图谱，报告了第一步和第二步各一个数字；我们量的是这几步之间的传递：OCR 变好之后抽取还丢多少（RQ1），要求证据有没有用（RQ3），以及名字能不能对到分类库（实体消歧）。上面第 4、5、6 条正对应我们的 RQ3、实体消歧和 RQ1。
- **他们转向 LLM 的理由，和我们在 ADEPT 复现里看到的一致**：定制流水线准但贵、难迁移。我们在开发集上看到的另一面是，LLM 在干净文本上几乎不出错，错误集中在 OCR 损坏的文字上，而且两个模型会照抄同一处损坏（一致不等于正确）。
- **粒度不同，分数不可比。** 他们的 HABITAT 是整句，我们是提及级的片段；他们的学名 F1 的匹配规则未知。这再次说明不能把 96.15% 和我们的数字放在一起。
- **他们的资源和计划**（一年全职、5 万英镑、Mistral OCR 重做全库）说明 OCR 这一层他们会解决。我们不做 OCR 基准这个决定是对的；有价值的是告诉他们：OCR 换新之后，下一个该投入的地方在哪里。

## 5. 可以带去 Deep Matters 的问题

1. 学名抽取的 96.15% 用的测试集和匹配规则是什么？人名、地点、机构有没有对应的评估？
2. 换成 Mistral OCR 之后，同一批页面上的实体抽取结果变化有多大？有没有哪类实体在好 OCR 下仍然不行？
3. 抽到的名字对到 PKB 实体这一步，历史异名和缩写属名（`A. gulgula`）怎么处理，准确率怎么量？
4. "对照图谱检查"在实际流程里拦下了多少比例的输出？有没有图谱里没有、但文献里是对的名字被误拦？
5. 生境这种整句级的实体，边界怎么定、怎么评估一致性？
