## 3. 逐项内容

### A. Enhancing Botanical Knowledge Graphs with Machine Learning（2022）[正式]

- **数据**：NHM 植物学采集人数据库（105,780 个实体）；NHM 印度地区植物标本数据集（110,043 个带地理信息的实体）。
- **方法**：把标本和采集人编码成知识图谱，用关系图卷积网络（RGCN，Schlichtkrull 等 2018）补全图谱缺口；
  结合度量学习（Xing 等 2002）做实体分类和链接预测。
- **结果**：第一阶段训练后，实体分类准确率 88%；链接预测给出 MRR，摘要里只说"合理"，没给数值。
- **设想的用途**：
  - 改进 OCR 后纠错，提高标本标签上实体识别的准确率；
  - 给人工转录提供"推荐读法"（人在回路）；
  - 对齐不同机构的图谱，找出重复、可能鉴定错误的标本、采集人的重要性、地理空白。
- 引用了 Rod Page 2019 的 Ozymandias 生物多样性知识图谱。

### B. PKB: Semantic Transcription Using Graph Neural Networks（2023）[正式]

- **合作方**：AWS（致谢 AWS Global Impact Computing Team）。
- **数据**：GBIF 中全部植物类群和标本，加上 GeoNames（地理）、Wikidata、Bionomia、Harvard Index of Botany、
  TL2、Tropicos（人物和文献）。第一个概念验证超过 **1 亿个节点**。
- **主要用途**：自动转录标本标签。先用 AWS 的 OCR 和自然语言处理服务从图像中取出文字并识别信息单元，
  再用图卷积网络把标签文字对齐到图谱里的实体，得到结构化的语义数据。
- **其他设想**：标记因分类学变动需要重新鉴定的物种；发现同一物种在不同来源里名称或分类不一致；
  找出可能被误鉴定的新种；与 IUCN 红色名录交叉核对。
- 计划做成云服务，供其他机构使用。

### C. 昆虫抽屉扩容估计（2026，Living Data 2025）[正式]

与 BHL 无关，但能看出团队怎么做和报告评测。

- **背景**：NHM 有 3,600 万件针插昆虫标本（约 13 万个抽屉），数字化时每件要加一个带 Data Matrix 条码的
  标签，可能让抽屉放不下。
- **数据**：Index Lot 收藏中 11,090 个已数字化的鞘翅目抽屉图像。
- **模型结果**：所有类别平均 mAP 85.45%；条码检测 86.63% mAP；标准单元盒检测和类型分类准确率 99.5%。
- **三种扩容率**（带 95% 置信区间，且列出了各自优缺点）：
  - 按抽屉多边形掩膜：12.25%（12.04–12.46）
  - 全局总量：19.06%（无区间）
  - 按单个标本外框：21.90%（21.80–22.00）
- 代码说会随正式论文开放。

### D. 被子植物性状数据集（2026-02-13）[正式]

数据来自 NHM 数据门户的 CKAN API（`package_show`），网页本身拒绝了自动抓取。

- **作者**：Ana Claudia Araujo; Ben Hartley; Neil Brummit（原文拼写）。维护人 Ben Hartley。CC-BY。
- **分类骨架**：World Flora Online（WFO）的全部被子植物接受名。
- **文本来源**：BHL（OCR 文本）、eFloras（Flora of North America、Flora of China、Flora of Pakistan 等）、
  Ecological Flora Database（Ecoflora）。
- **规模**：59,369 个被子植物物种，**888,328 个性状值**，覆盖生长型、株高、叶形态、花、果、种子、
  传播方式，以及部分细胞学信息（倍性）。
- **方法**（数据集说明原文概括）：机器学习分类找出植物描述 → 基于本体的术语匹配 → 数值性状的命名实体识别 →
  句法分析 → 基于规则的语义解释，把性状关联到植物结构并统一单位。
- **文件**（7 个 CSV，均已入门户数据库）：

  | 文件 | 内容 | 大小 |
  |---|---|---|
  | `wfo-angiosperms.csv` | WFO 被子植物物种 | 27.1 MB |
  | `combined.csv` | 所有来源合并 | 17.3 MB |
  | `bhl.csv` | 从 BHL 描述中抽取 | 28.5 MB |
  | `ecoflora.csv` | Ecoflora | 0.5 MB |
  | `efloras.flora_of_china.csv` | Flora of China | 7.4 MB |
  | `efloras.flora_of_north_america.csv` | Flora of North America | 3.1 MB |
  | `efloras.flora_of_pakistan.csv` | Flora of Pakistan | 1.0 MB |

- **数字前后不一致，需核实**：BHL Day 演讲（F）说"约 706,000 个性状值、81 个功能性状、106,000 条描述、
  59,000 个物种、全部 342,000 个接受的被子植物物种"；数据集说 888,328 个性状值；评测包（E）用的是
  80 个性状字段。可能是版本不同，也可能一个数的是"值"、一个数的是"词"。59,369 / 342,000 ≈ 17%，
  和 TDWG 讲座（G）说的"覆盖 17% 的被子植物接受名"一致。

### E. ADEPT 代码库和评测包 [正式]

- **流程**：
  - 用 BHL 的名称索引（从 BHL 数据归档建立）找到提到某个物种的页面；
  - 读 BHL 的 OCR 全文导出（Richard & Dearborn 2022，Smithsonian，[doi:10.25573/data.21422193.v22](https://doi.org/10.25573/data.21422193.v22)），
    或者改用本地 Tesseract 重新 OCR（`--ocr TESSERACT`）；README 明说默认的 BHL OCR "may contain OCR errors affecting downstream trait extraction"；
  - 二分类器判断一段文字是不是正式的物种描述（BHL 里叙述和描述混在一起）；
  - 规则匹配抽性状；用 Luigi 编排；BHL 请求有缓存。
- **模型**（spaCy，transformer）：
  - 描述分类器 [benhartley/en_description_classifier](https://huggingface.co/benhartley/en_description_classifier)
  - 数值性状 NER [benhartley/en_adept_ner_trf](https://huggingface.co/benhartley/en_adept_ner_trf)
- **训练配置的一个细节**：分类器的 `project.yml` 在训练命令里把 `test.spacy` 作为 `--paths.dev`（训练中用于选模型的验证集）。
  如果论文报告的测试分数也来自这个文件，那它就不是独立的保留集。没有看到论文，未核实。
- **评测包**（`notebooks/adept_evaluation/`，README 说"可在 Overleaf 中引用"，似乎是论文附录）：
  - 50 条记录、49 个类群、80 个性状字段；参考答案和预测由 Ben Hartley 提供（"revised reference"）。
  - README 和 `evaluation_settings.json` 都明说：**"Development descriptions, not an independent held-out test"**。
  - 匹配规则：规范化后精确集合匹配，不合并同义词，数值没有容差；参考为空表示"没有相关信息"。
  - 文件留有参考和预测的 SHA-256、Python 和 pandas 版本、逐格得分和全部不一致项（252 条）。
  - **总体（micro）**：精确率 0.905，召回率 0.832，F1 0.867（参考 1,299 个值，预测 1,194 个，TP 1,081）。
  - **按来源**（由 `cell_level_scores.csv` 汇总，我们自己算的）：

    | 来源 | 记录数 | P | R | F1 |
    |---|---|---|---|---|
    | BHL | **3** | 0.82 | 0.79 | 0.80 |
    | Ecoflora | 12 | 0.95 | 0.88 | 0.92 |
    | Flora of China | 12 | 0.92 | 0.84 | 0.88 |
    | Flora of North America | 15 | 0.86 | 0.80 | 0.83 |
    | Flora of Pakistan | 8 | 0.93 | 0.83 | 0.88 |

    BHL 只有 3 条记录（Rumex conglomeratus、Mentha aquatica、Plantago lanceolata），而 BHL 是数据集里最大的来源（`bhl.csv` 28.5 MB）。
  - **较弱的字段**：被毛（indumentum）F1 0.62（召回 0.48），花序排列 0.48（召回 0.31），株高召回约 0.78–0.80，叶形 0.86。
    数值和分类字段的精确率普遍高于召回率。

### F. BHL Day 2026 演讲（Hartley, Gu, Smith）[讲稿]

15 页幻灯片，前半由 Hartley 讲，原型部分由 Gu 讲。

1. **BHL 的价值**：6,300 万页、30 万卷、20.3 万种题名、2.6 亿次物种名出现。
2. **"文献是储存层"**：一篇 2002 年的论文 4 页里有 142 个"原始"数据点。把数据从文献中解放出来的
   "biodiversity data prison break"；致敬 Plazi。
3. **性状抽取（幻灯片写 ADAPT，代码库名为 ADEPT）**："Harriet 和我做了五年"（"Harriet" 可能是转写错误，
   数据集作者里没有这个名字，需对录像核实）。对 342,000 个接受的被子植物物种运行，约 706,000 个性状值、
   81 个性状、106,000 条描述、59,000 个物种；只限英文文献。
4. **局限**："不能为每个问题都做一条定制管线"；需要可推广的 AI 基础设施。
5. **转折**：从针对单一任务的 transformer 转向 LLM；LLM 的挑战是计算成本、幻觉、需要下游处理和验证。
   原话："The question is no longer simply whether we can use LLMs; it is how to build the infrastructure that allows us to use them reliably and at scale."
6. **原型**：2 种期刊（1865–2017），35,721 页；端到端流程 OCR → 实体 → 知识图谱；与 AWS 原型团队合作，4 周快速原型。
7. **流程和指标**（幻灯片原文）：
   - OCR Accuracy 99.57%（口述为"词级准确率高于 99%"，"现代成熟的 OCR 模型"）；
   - 首页识别：无目录 98.76%，有目录接近 100%；
   - Taxon Extraction F1 96.15%；
   - 实体用"云端大语言模型"抽取：学名、生境、地名、机构；之后标准化并建图谱；同时抽取插图、图版、表格。
   - **没有说明**：指标在多少页、哪些期刊上算的，金标准谁标的，是否独立于开发集，以及 F1 是按提及还是按值算。
8. **界面**：按实体类型过滤、按颜色高亮实体、每篇文章自动生成摘要；有现场演示。
9. **能带来什么**：多语言检索（含拉丁文）、以图搜图并识别图中的类群；关联到藏品记录、机构名录、Wikidata。
10. **PKB**：基础模型 + 知识图谱；用图谱"核对生成的说法"以减少幻觉。
11. **申请的资源**：1 年全职软件工程师或数据科学家、Gu 的投入、**5 万英镑用于云计算和 Mistral OCR**；
    重新 OCR 全部 BHL，并把改进后的 OCR 开放给 BHL 社区；把文章切分和实体抽取做成生产级模型；
    原计划做 InvenioRDM 原型，会上讨论后改为在现有 BHL 界面旁边做知识图谱检索原型。

### G. TDWG 2026，Gu（9 月 22 日）[机器摘要；摘要正文是作者写的，数字来自机器概述]

- **定位**：帮助 BHL 变成机器可操作、符合 FAIR 的基础设施，并与 PKB 连接；做一个"知识抽取和发现层"，
  每条结果都能回链到 BHL 的页面、出版物和元数据。
- **原型流程**：现代 OCR、文章切分、图表抽取、分配持久标识符、实体抽取。
- **实体类型**：学名、人名、机构、地名、标本编号、生境、地层。
- **对外关联**：GBIF、Catalogue of Life、Wikidata、GRSciColl；**带出处回到 BHL 原页，并带置信度元数据**。
  数据集定位为 PKB 的"证据层"。
- **机器概述里的数字**：
  - 4 周 AWS 原型，处理"不到 40,000 页"的一份植物学期刊（F 说的是 2 种期刊、35,721 页，需核实是否同一次）；
  - 首页识别约 98%，有目录约 100%；实体抽取 F1 约 96%；
  - 知识图谱加 GraphRAG 检索；
  - 用 BHL 提供的金标准做基准测试，印刷体达到"人类水平的转录"；
  - **用词级 OCR 置信度决定哪些结果写回 BHL**；
  - 从前每个任务要一个专门模型，现在 LLM 和视觉语言模型一次处理更多。
- **时间表**：全库重新 OCR 约 2027 年 1 月完成；**2027 年初发布开放的金标准数据集**；Explorer 界面 2027 年第二季度。
- 没有说明 OCR 模型名称。

### H. TDWG 2026，Smith（9 月 25 日）[机器摘要]

- **PKB 的设想**："an infinite solutions engine"：生物多样性基础模型（用文献、标本记录、观察、图像、基因和环境数据训练）
  加上保留出处的知识图谱（物种、标本、性状、相互作用、变化）；用 RAG、API 和自然语言界面降低幻觉；
  支持情景探索，服务于恢复、迁移和韧性规划的生态建模。
- **机器概述里的内容**：
  - 处理规模"每天 10,000–20,000 条记录"；PKB 第一阶段进行中；
  - **BHL"几乎已全部用 Mistral 重新 OCR"**，并在其上抽取机构、学名、标本、文章，做成新的 BHL 发现层；
  - SCRIBE 用于转录卡片索引、标签和植物标本台纸；
  - "Museum Digital Backbone"：用 Amazon Quick 在内部不可共享的数据上做的小型知识图谱 + LLM；
  - 设计原则：每一步保留标识符、出处和许可；署名；利益共享（可能包括报酬机制）；问答涉及 CARE 原则和对 AWS 的依赖。
- 没有给评测指标或成本。

### L. BHL 现有 OCR 与"全库重新 OCR" [正式 / 讲稿 / 机器摘要，逐条注明]

**现有 OCR 从哪来**：BHL 的扫描大多由 Internet Archive（IA）完成，IA 扫描时生成每页的 OCR 文字层；2020 年以前
用 ABBYY FineReader，2020 年起用 Tesseract；基本没有人工校对
（[BHL OCR 说明](https://about.biodiversitylibrary.org/?p=2890) [正式]）。BioEvidenceBench 的 legacy OCR 就是这层文字，
取自 `bhl-open-data.s3.amazonaws.com/ocr/`（`src/common.py`）。

**已知质量问题**：BHL 2008 年评估，3,003 个学名中有 1,056 个（35%）被 OCR 读错
（[BHL 博客 2008-10](https://blog.biodiversitylibrary.org/2008/10/evaluation-of-taxonomic-name-finding.html) [正式]）。

**BHL 自己的重处理（2022 起）**（[OCR Improvements: An Early Analysis，2022-07](https://forums.botanicalgarden.ubc.ca/threads/ocr-improvements-an-early-analysis.102585/) [正式，BHL 博客转载]）：
- 估计重处理全部约 3,500 万个文本项目需要数年，并占用收集新内容的资源；
- 先选 8 万个用 ABBYY FineReader 8.0 处理的项目试点，另有约 39,500 个缺少 OCR 标记的项目随后处理；
- 与 Global Names Architecture 合作看学名识别：一个样本里不重复学名从 20 增至 38；6 个项目的表里有从 641 增至 920 的，
  也有不变的；
- 做法（BHL 后续博文，见 [tesseract 标签页](https://blog.biodiversitylibrary.org/tag/tesseract)）：在 IA 删掉几个关键文件，
  发出 "derive" 命令重新生成 OCR，并更新 "OCR" 元数据值；每个项目需几十分钟到几小时。

**NHM 的全库重新 OCR**：
- 申请 5 万英镑用于云计算和 Mistral OCR，重新 OCR 全部 BHL 并把结果开放给 BHL 社区（F [讲稿]，第 11 条）；
- 约 2027 年 1 月完成；2027 年初发布开放金标准；用词级 OCR 置信度决定哪些结果写回 BHL；没有说明模型名称（G [机器摘要]）；
- "BHL 几乎已全部用 Mistral 重新 OCR"（H [机器摘要]），与 G 的时间表关系待核实（第 5 节第 4 条）；
- Mistral 版本之间可能退步：`mistral-ocr-4-1` 比 `mistral-ocr-2512` 读出文字错误率高（J [第三方]）。

**同类工作**：FineBooks（Hugging Face + EleutherAI）用开源模型重新 OCR BHL，并公布排行榜和逐页输出（见 CLAUDE.md 第 2 节、
`src/fetch_modern_ocr.py`）。

**规模**：BHL 自述约 6,200 万（2024 年公告）到 6,400 万页。按 5 万英镑和 6,400 万页摊算，每千页不到 0.8 英镑（含云计算；
本笔记的算术，没有对照 Mistral 价目）。

**没有找到**：新 OCR 是否带词级坐标（Mistral 输出是 Markdown）；新旧文字层并存还是替换；模型版本和出处如何记录。

## 4. 与 BioEvidenceBench 的对应

只列事实对应，不作评价。**两边分数不可比**：样本、实体定义、匹配规则都不同。

| NHM 材料里的做法或数字 | BioEvidenceBench 里对应的东西 |
|---|---|
| 整页 OCR 准确率 99.57%，"人类水平" | 22 个 OCR 版本上，整页错字率预测不了抽取效果，学名保留率能（Spearman 0.95 / 1.00，探索性） |
| 实体抽取 F1 96.15% / 约 96% | 我们报的是按提及、值级 F1，按书分别报，带页级区间；现代 OCR 上 0.95 / 0.98（预注册） |
| 实体关联到 GBIF、CoL、Wikidata、GRSciColl | 直接查 GBIF，34 个已正确抽出的鸟类学名丢 14 个（预注册）；LLM 关联器 0.59 → 0.91（探索性） |
| 带置信度、回链 BHL 原页的出处 | 行号 + 逐字引语由代码核对；图像坐标应来自 OCR 词坐标，视觉模型画框只有 67% / 40% 命中 |
| 用词级 OCR 置信度决定写回什么 | 审核分流：旧 OCR 上两条便宜检查用 25% 的审核量抓到 55% 的错误 |
| ADEPT：BHL 名称索引找页 + 描述分类器 | 我们用 TaxonFinder `page_name` 做页级基线和分层抽样；发现它会把有实体的页分进"无实体"层 |
| ADEPT 评测：50 条开发记录，明说不是保留测试；参考由作者提供 | 我们的测试集 16 页锁定，冻结后才运行；第二标注者 5 页 |
| ADEPT 评测包：SHA-256、版本、逐格得分、`evaluation_settings.json`、`discrepancies.csv` | 我们的分析输出用了同样的文件名和思路（`analysis.py`） |
| 2027 年初开放金标准 | 下一轮可以用的数据；可在上面跑学名保留测试 |
| 全库用 Mistral 重新 OCR | 我们建议的验收方式：在标注样本上测学名保留率，按材料类型分别测 |
