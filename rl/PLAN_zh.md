## 0. 目标和边界

**一句话**：把 BioEvidenceBench 这个评测，延伸成"可验证的环境 + 被审计过的验证器 + 一次真实的小规模 RL 训练"，并用同样的纪律检查奖励函数、训练效果、题目难度和版本发布。

**主线不变**：BioEvidenceBench 的主线是"从历史文献到可信数据，评测每一步的可靠性"。`rl/` 讲的是下一步："把这个评测变成训练环境，检验它的奖励函数，并用它真的训练一次。"

**要回答的问题**（训练部分是待检验的假设，不是预设的结论）：
1. 现有评分器和新奖励函数会被怎样钻空子？
2. 以"受损词"为单位、对学名加权的奖励，是否比以字符为单位的奖励（1 − CER）更能让模型修好科学上重要的信息，同时不破坏原文？
3. 在已有完整专家转录（可以直接做 SFT）的情况下，GRPO 能否带来额外的、在留出数据上站得住的改进？
4. 改进来自哪里，代价是什么？

**硬规则（继承自 CLAUDE.md）**

1. **冻结的研究一字不动**：`FREEZE.json` 列出的文件、`PREREGISTRATION.md`、金标准文件都不改；每次提交前 `python src/freeze.py --verify` 必须干净。`rl/` 只**读取**冻结代码；要改的地方在 `rl/` 里写副本。
2. **测试页不当训练题**：22 个样本页（6 开发 + 16 测试）和第 3 节封存的 16 页，永远不进任何训练集。
3. **旧测试集降级**：16 个测试页对 `rl/` 的所有新工作来说是开发集；在它们上得到的新数字，不能称为保留测试结果。
4. **标注和判断由 Gloria 做**：Claude 不写、不预填任何标签（学名身份标签、审题结论、奖励设计取舍、通过标准）。Claude 可以生成候选、做程序检查、做统计、起草文字。
5. **只用公开数据**；模型不改写原文。任务 B 的"修复"输出只作为被评分的回答，从不写回任何源文本。
6. **每次运行可复现**：`results/<run_id>/` 存模型名和版本、完整提示词、输入哈希、解码或训练设置、原始输出、时间戳、花费；训练运行另存框架版本、全部超参数和随机种子。
7. **花钱前先试跑**：任何付费批量先跑约 5 个样本报告单价；GPU 训练先跑一个很短的试跑报告每小时成本，再按上限运行。
8. **记录位置**：`rl/` 的决定和偏离写在本文件第 14 节和 `rl/LOG.md`，不写进 `DEVIATIONS.md`（那份只记原研究的偏离）。

**不进公开仓库**：求职计划、故事库、案例题答案、读书笔记。模块一（外部基准审计）放在单独仓库 `benchmark-audits`（需要 Gloria 在 GitHub 上新建）。

## 6. 任务 B：OCR 修复的可训练环境（Phase 1 核心）

### 6.1 任务

单轮：`提示 → 回答 → 奖励`。提示给出一行（或一小段）旧 OCR，加前后各一行上下文；要求"把它改回原书的样子：只改识别错误，不改书中的拼写、连字、长 s 和写法"。

### 6.2 数据构建和词对齐

这是最容易出错的部分。

- **两次对齐**：
  - **对齐 A：旧 OCR ↔ 专家转录**：确定参考文本里哪些词原本受损（集合 D）、哪些原本正确（集合 C）；
  - **对齐 B：模型输出 ↔ 专家转录**：判断受损词是否修好、原本正确的词是否被改坏或丢失。
- **必须显式处理**：一个词被拆成两个、两个词被合成一个、跨行断词和连字符、连字、标点移动造成的分词边界变化。不能简单按空格切开后按位置比较。
- **对不齐的样本**：标记出来，不计分，报告比例；不硬造词级标签。
- **Unicode**：只做 NFC。**不用 NFKC**，它会把长 s、连字等兼容字符改成别的形式，再声称"逐字一致"就不成立了。现有评分器的 `norm_value` 会折叠连字符和引号，奖励里不沿用。
- **题目粒度**：优先选含 **2–5 个受损词**的行或短段（只有一个受损词时，奖励只有 0 或 1，GRPO 信号太弱）；另外保留约 **20% 的干净行**，检验模型会不会乱改。
- **对齐质量审计**：
  - 程序检查：对齐置信度分布、拆分合并的比例、可疑样本清单；
  - Claude 逐条检查 100 个跨书、跨语言、跨错误类型的行对，统计对齐错误率；
  - **Gloria 抽查其中 30 个**（约 15 分钟），作为独立核对；
  - 训练前报告：过滤掉多少、对齐错误率多少。

### 6.3 奖励 Reward v1.0（作为待检验的假设）

定义：D 为旧 OCR 中被读错的词，C 为原本正确的词；wᵢ 为受损词的权重（学名候选 3，普通词 1）；x̂ᵢ 为模型输出中与参考词 xᵢ 对齐的词；B 为原本正确、却被模型改错、删除或丢失的词数；λ 为破坏扣分强度（初值 1.0，在开发集上校准）。

**有受损词的行**：

```
R = Σ_{i∈D} wᵢ·1[x̂ᵢ = xᵢ] / Σ_{i∈D} wᵢ  −  λ · min(1, B / max(1, |D|))
```

- 前一项：**加权受损词修复率**，逐字完全匹配才算修好，不给字符相似度的部分分；
- 后一项：**保留扣分**，防止"多改多得"、现代化拼写、拆开连字。

**干净行**（D 为空）：**保留奖励**：完整保留原文得 1；每改坏一个词按比例扣分。

**完整性检查**（独立于上面两项）：删除大段文字、只输出修好的词而丢掉其余内容、输出多行或整段等结构错误，奖励记为 0 并单独计数。

**例子**（λ = 1，且假设 gnfinder 正确识别了学名）：旧 OCR `Muscicapa parua recorded in specirnens.`，专家转录 `Muscicapa parva recorded in specimens.`；`parua → parva` 权重 3，`specirnens → specimens` 权重 1。

| 模型行为 | 奖励 |
|---|---|
| 两个都不修 | 0.00 |
| 只修好普通词 | 0.25 |
| 只修好学名 | 0.75 |
| 两个都修好 | 1.00 |
| 都修好，但改坏一个原本正确的词 | 0.50 |

**CER 只作诊断**：报告，但不进入奖励。理由：原研究发现页面 CER 预测不了学名是否被保留（Spearman −0.07 / −0.62），学名保留率才行（0.95 / 1.00）；一个字母的错误几乎不改变 CER，却能让学名失效。

**这是"分级离散"奖励，不是连续奖励**：只有一个受损词的行，奖励仍然只有 0 和 1。所以题目粒度和难度校准（6.7、模块五）很重要。

### 6.4 学名候选（gnfinder）的噪声

- 学名候选由 gnfinder 在专家文本上自动识别。原研究中它作为规则基线的学名 F1 是 0.54–0.64，但那是实体抽取设置，**不等于**它在"识别受损学名词"这个新任务上的准确率。
- **单独测量**（用 22 个样本页的人工金标准，只作诊断，不作盲测；据此修改奖励的过程记入日志）：

| 指标 | 问题 |
|---|---|
| 学名词精确率 | 被加权的受损词，有多少确实属于学名？ |
| 学名词召回率 | 应当加权的受损学名词，有多少被漏掉？ |
| 奖励敏感性 | gnfinder 的误识别，是否让某些错误回答拿到过高奖励？ |

- gnfinder 的噪声**会影响模型学到的行为**（加权后的总奖励依赖它），不只影响报告。所以训练中比较 **w = 1（不加权）** 与 **w = 3（学名加权）**：如果加权后学名修复率上升、普通词明显退化，或者在 gnfinder 漏掉的罕见学名上表现差，就说明权重要调。

### 6.5 奖励的对抗测试（写进 `REWARD_AUDIT.md`）

原样返回；返回空；过度改写；把书中拼写现代化；拆开连字或把长 s 改成 s；只改简单字符、回避学名；删掉难词；输出多行或整段；在干净行上乱改。每种构造若干例子，看 Reward v1.0 和 1 − CER 分别给多少分。

### 6.6 污染检验（内置）

- **虚构名称**：把专家行里的真实学名换成拼写合理但不存在的学名，加上同样的 OCR 噪声（程序生成，答案已知）。靠记忆的模型在虚构名称上会明显变差。
- **反事实改动**：改地名或日期，看模型修复出来的是页面上写的，还是它记得的原值。

### 6.7 组内奖励差异（GRPO 的前提）

GRPO 的优势 = 奖励减组内均值（除以组内标准差）。一组回答奖励全一样，这道题不产生学习信号。所以要测：每题采样 K 次（默认 8），**组内奖励有差异的题占多少比例**（TRL 的日志里可能有相应指标，如 `frac_reward_zero_std`，使用前核对文档）。影响这个比例的设计：题目粒度（2–5 个受损词）、干净行比例、采样温度、每组采样数。

### 6.8 试跑和产出

- 用 2 个 API 模型 × 约 200 题试跑（只用训练和开发块，不碰任何测试集），检验奖励和对齐能否正常工作。
- **产出**：`rl/env/task_b_ocr_repair/`（构建脚本、数据清单和哈希、对齐审计、试跑结果）、`REWARD_DESIGN.md`。
- **Gloria**：决定奖励设计（λ 的范围、w 的取值、干净行比例）；抽查 30 个对齐；审对抗测试结果。约 1.5 小时。
- **花费**：约 $3。

## 7. 模块七：真实训练（Phase 1 核心）

### 7a 玩具版 GRPO（$0）

约 50 行 Python，在 CPU 上逐步实现并可视化：采样一组回答 → 算奖励 → 组内归一化得优势 → 概率比乘优势并截断（同 PPO）→ 可选 KL 惩罚 → token 级损失汇总。配讲解笔记，回答：组内奖励全一样会怎样；采样数、温度、KL 系数的影响；奖励尺度；按 token 平均是否偏向长或短回答（如 Dr. GRPO 的分析，引用前核实）；动态过滤全对或全错的组（如 DAPO，引用前核实）。产出 `rl/training/toy_grpo.py`、`NOTES_zh.md`。

### 7b 训练实验

- **工具**：Hugging Face TRL（`SFTTrainer`、`GRPOTrainer`，接 `reward_functions.py`）。不自写优化器。开工前读当前文档，锁定版本。也可参考 Prime Intellect 的 `verifiers` 学习环境的写法，但第一轮只用一个框架。
- **模型**：0.5B–1.5B 的开源模型（候选如 Qwen3-0.6B，开工前核实），可能需要 LoRA 和 vLLM。
- **核心对照**（同一基础模型、同一数据划分、尽量相同的训练计算量）：

| 条件 | 目的 |
|---|---|
| 原样返回旧 OCR | 不训练的操作基线 |
| A. Base | 基础能力 |
| B. SFT | 用专家转录直接监督，能教会多少 |
| C. GRPO | 只用可验证奖励能带来多少 |
| D. SFT → GRPO | 先监督、再强化，是否更有效 |

- **奖励消融**（只在 GRPO 条件上做）：先跑 **R-A：1 − CER** 与 **R-D：Reward v1.0**；预算允许再补 **R-B：受损词修复率（不加权）** 和 **R-C：R-B + 学名加权**，用来拆开"词级单位""学名加权""破坏扣分"各自的作用。
- **随机种子**：每个主要条件至少 2–3 个。
- **事先定好的主要指标**（写进 `rl/training/configs/METRICS.md`，训练前提交）：受损词修复率、学名逐字恢复率、原本正确词的保留率、CER（诊断）、格式和完整性失败率、奖励被钻空子的比例（用 6.5 的检查）；分别在同书内测试和 Cuvier 留出书上报告。**训练奖励不能当作唯一的成功指标。**
- **训练过程记录**：奖励、组内奖励标准差、组内无差异的比例、KL、输出长度、各检查点的指标。
- **小模型太弱的应对**：几乎全错（组内没有差异）时，先用 SFT 把模型"带上路"（这正是条件 D），或换更简单的子集，如实记录。
- **硬件**：这个云环境没有 GPU，需要 Gloria 的账号租用（如 Hugging Face Jobs、Colab、RunPod）。**先做短试跑，报告每小时成本**。**GPU 总预算硬上限 $20**（Gloria，2026-11-21，先定 $10，后改 $20；不用 Kaggle）：排错、试跑、正式运行都在 RunPod 上，默认 RTX 4090 社区云（约 $0.34/小时），全部计入 $20；GRPO 每个条件 3 个种子，奖励消融 2 个种子，步数（约 300–500）在试跑后定，评测用固定的 500 行子集。API 推理、GPU 训练、rollout 生成、存储、人工审核的花费分开记录。
- **产出**：`rl/TRAINING_REPORT.md`。即使 GRPO 没有超过 SFT，只要实验可靠、能解释原因、能提出下一轮实验，结果同样有价值。

### 7c 改进归因

奖励上升不算数。`TRAINING_REPORT.md` 按四个问题依次回答，每项写清数据和方法：

1. **真的变好了吗？** 在不参与训练和奖励调参的数据上，用 7b 的主要指标判断；对照训练前模型和"原样返回"基线；多个种子；置信区间按页块重抽样；Gloria 人工抽检约 50 行。
2. **在哪里变好？** 按错误类型（学名字母、普通单词、连字、长 s、数字、标点、断词）；按改动行为（改动率、改动精确率、改动召回率，区分"改得更多"和"改得更准"）；按训练前难度（0%、10%–90%、100% 三组）。
3. **为什么变好？** SFT 与 GRPO 的对比；奖励消融；训练前 pass@k 与训练后 pass@1（判断是"学会了"还是"更稳定地给出本来就能给的答案"，相关讨论如 Yue 等 2025，引用前核实）；真实学名与虚构学名；同书内与 Cuvier；逐行读"训练前错、训练后对"和"训练后反而变错"的例子。
4. **代价是什么？** 任务 A 等其他任务上的副作用；"奖励涨、留出指标不涨"或"输出变怪"的时刻。

### 7d 发布决定

`rl/RELEASE_DECISION.md`：哪个检查点（或不发布）、依据哪些事先定好的标准、哪些改进有统计和实际意义、有哪些退化、是否值得继续投入训练资源。标准由 Gloria 在看结果之前写好。

## 8. 模块四：失败审计链和数据优先级（Phase 2）

### 审计对象：可观察、可复现的链条

```
输入 → 可观察的模型输出 → 工具调用 → 证据 → 验证器结果
```

| 环节 | 在本项目里是什么 | 记录在哪 | 可否复现 |
|---|---|---|---|
| 输入 | 带行号的页面文本（版本和 SHA-256）、提示词版本 | `inputs.csv`、`prompts/` | 是 |
| 可观察的模型输出 | 原始回答、结束原因、用量 | `test_outputs.jsonl` / `outputs.jsonl` | 是（存档）；重跑会略有不同 |
| 工具调用 | 关联环节：模型给出名称 → GBIF 查询及返回 | `linking_variants*/llm_calls.jsonl`、`gbif_*.jsonl` | 是（缓存） |
| 证据 | 代码定位的行号和引语、字符对齐到专家转录的位置 | `test_mentions.csv` | 是 |
| 验证器结果 | 评分器对每个提及和金标准项的结果 | `score.py` 的 outcomes | 是 |

- **定位错误只依据这条链**：记录链条所有断开的环节（可多选，标出最早一处），和原研究的错误标签一样允许多种原因。
- **思考摘要的定位：证词，不是证据**。它不等于完整的内部推理，也不能证明错误发生在内部计算的哪一步；报告中单列为"模型的自我解释"。用途：提出假设、发现钻空子的苗头；并**测量忠实度**（摘要说的和链条是否相符）。已有研究发现模型陈述的推理常常不忠实（如 Turpin 等 2023；Anthropic 2025《Reasoning models don't always say what they think》；引用前核实）。
- **干预实验**：改动输入的一处，看输出是否随之改变（把证据区间的 OCR 错字改回、去掉或加上前一页上下文、把真实学名换成虚构学名、同一请求换路径重发）。结果说明的是**输出对这处输入敏感**，不是内部机制。

**案例**（约 20 个，Claude 生成候选，Gloria 确认）：旧 OCR 上照抄误读的学名（Opus、Gemini，5）；返回空列表（Gemini，1–2，偶发）；学名关联错误（Opus、Gemini，5）；长页漏抽（Sonnet，3）；通顺的 OCR 错误没修出来（Opus、Gemini，3）；抽检中的范围外输出（Opus，2）。

**步骤**：先用现有记录建链（不花钱）；干预实验每个跑 3 次；思考摘要（Claude `display: "summarized"`，Gemini `include_thoughts`，提示词沿用冻结版本），报告复现率；按断开环节分类（输入、输出、工具调用、证据、验证器、金标准或范围）；写数据优先级备忘录（现成依据：关联环节模型差距 0.76–0.94，抽取 ≤0.05；标注成本：抽检约 30 秒一条，关联约 3 分钟一个名字）。

**产出**：`audit_chain.csv`、`traces/`、`TAXONOMY.md`、`DATA_PRIORITY.md`。**Gloria**：1–2 小时。**花费**：建链 $0，其余约 $3–5。
