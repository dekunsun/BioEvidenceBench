# 模块 7a：玩具版 GRPO 讲解笔记

*2026-11-21。代码 `rl/training/toy_grpo.py`（numpy，CPU 上 20 秒，$0），结果 `results.json`，
图 `figures/toy_grpo_curves.png`。*

## 1. 这个玩具是什么

把任务 B 缩小到能手算的程度：

- **一道题 = 一行**。行长和受损词数直接取自真实开发集（3,784 行），受损的学名词算"难"，其余受损词算"易"。
- **一个 token = 对一个词的处理**，三选一：保留 OCR（KEEP）、改成正确的词（FIX）、改成别的词（OTHER）。
- **奖励用 Reward v1.2 的公式**：加权修复率减去 0.5 × 改坏数，学名权重 3。
- **策略是一张 3×3 的 logits 表**（行：干净、易受损、难受损）。softmax 策略的梯度可以直接写出来：∇log π(a|s) = (onehot(a) − π(·|s)) / T。所以每一步更新都能逐项核对，不依赖自动求导。

**它不是语言模型。** 各个 token 互相独立，没有对题目的理解，也没有共享表示。它演示的是 GRPO 怎样把奖励变成更新，不代表一个 0.6B 模型会怎样学。各变体用同一个学习率、没有分别调参，所以比较的是机制，不是"哪种算法更好"。

## 2. 一步 GRPO 做了什么（`grpo_step`，约 50 行）

1. **采样**：每道题用旧策略采 G 个回答（默认 8）。
2. **算奖励和优势**：优势 = 奖励 − 组内均值，可选再除以组内标准差。**同一个回答里的所有 token 共用这个优势。**
3. **截断的策略比率**（同 PPO）：ρ = π_new(a)/π_old(a)，目标是 min(ρA, clip(ρ, 1−ε, 1+ε)A)。截断后的项梯度为 0，防止一次更新走太远。
4. **可选 KL 惩罚**，把策略拉向参考策略（k3 估计量）。
5. **把 token 项汇总成损失**：
   - `grpo`：先在每个回答内取平均，再在回答之间平均；
   - `dapo`：所有 token 求和，除以 token 总数；
   - `dr_grpo`：求和，除以常数 G × 最大长度。

## 3. 计划里要回答的问题

### 3.1 组内奖励全一样会怎样？

优势全是 0，梯度为 0，这道题这一步什么也学不到（DAPO 论文的原话是 zero advantage results in zero policy gradients）。

**训练开始时，信号为零的组的比例**（E1，600 题模拟）：

| 温度 T | G = 2 | G = 4 | G = 8 | G = 16 |
|---|---|---|---|---|
| 0.5 | 82% | 66% | 63% | 59% |
| 1.0 | 65% | 49% | 27% | 15% |
| 1.5 | 47% | 20% | 6% | 0.3% |

- **组越大、温度越高，全组一样的情况越少。** 代价是：组大了，每题的采样成本成倍增加；温度高了，回答更乱（格式错误增多）。
- **训练越久，这个比例反而上升**（图中间那张）。模型学会以后，很多题 8 次全对，信号随之消失。所以 TRL 记录 `frac_reward_zero_std`（文档原文："The fraction of samples in the generation batch with a reward std of zero"），训练中要盯着这个数。
- **对任务 B 的意义**：干净行几乎总是 8 次全对（第 5 步试跑：Opus 有信号的干净行只有 6%），所以干净行只起"不许乱改"的护栏作用，不提供学习信号；GRPO 的信号几乎全部来自有 2–5 个受损词的行。

### 3.2 动态过滤（DAPO 的 Dynamic Sampling）

DAPO 丢掉准确率为 0 或 1 的组，并继续采样补满批次（原文："prompts with the accuracy equal to 1 and 0"）。

- **玩具里的效果**（E2，3 个种子）：最终奖励 0.96，基线 0.93。
- **原因**：被丢掉的组本来就不贡献梯度，丢掉后有效的组在批次里占比更高，每步更新不被稀释。
- **代价**：要多采样，才能补满批次。

### 3.3 KL 系数

| 设置 | 最终奖励 | 离参考策略的 KL |
|---|---|---|
| β = 0 | 0.93 | 0.34 |
| β = 0.5 | 0.86 | 0.12 |

- KL 把策略拉住，学得慢一些，但离初始策略更近。
- TRL 的默认是 β = 0（文档原文："we use β = 0.0 by default"）。DAPO 也去掉了 KL 项，理由是长推理时模型本来就会离初始分布很远。
- **对任务 B**：防止模型"乱改"的主要靠奖励本身（改坏扣 0.5、插入扣 0.25、格式门控），KL 只是一层附加的保险。β 取多少留到 7b 用开发集决定。

### 3.4 奖励尺度和标准差归一化

把奖励乘以 10（E4）：

- **除以组内标准差时**，更新完全不变（比值 1.00）。
- **不除时**，更新变成原来的 10 倍（比值 10.00）。也就是说，不做标准差归一化时，奖励的尺度就相当于学习率。

Dr. GRPO（Liu 等，2025）认为除以标准差会造成"题目难度偏差"：方差小的组（太容易或太难）被放大。玩具里"不除标准差"那条曲线学得慢，主要是步长变小了，不能说明它更差。

### 3.5 按 token 平均会不会偏向长或短的回答？

同一个优势下，一条 5 个 token 的回答和一条 40 个 token 的回答放在同一批里（E3），每个 token 分到的权重：

| 汇总方式 | 短回答每个 token | 长回答每个 token |
|---|---|---|
| `grpo`（每条回答内先平均） | 0.100 | 0.0125（是短回答的 1/8） |
| `dapo`（按 token 总数） | 0.022 | 0.022 |
| `dr_grpo`（除以常数） | 0.0125 | 0.0125 |

- 按回答平均时，长回答里每个 token 的权重被摊薄。DAPO 指出，这会让又长又差的回答（乱码、重复）受到的惩罚不够。Dr. GRPO 指出，GRPO 会让错误回答越写越长。
- TRL 现在的默认 `loss_type` 是 `"dapo"`。文档把 `"grpo"` 标为"不推荐，有长度偏差"（这一句来自文档摘要，没读到原文全文）。
- **对任务 B**：回答长度大致等于行长（3–20 个词）。用 `grpo` 汇总时，长行的每个词得到的训练比短行少。所以 7b 用 TRL 默认的 `dapo` 汇总。

### 3.6 数据选择：玩具里最清楚的一条结论

- 按真实分布抽题时，所有变体都**学不会修学名**：P(修好 | 难词) 一直停在 0.07 左右。原因是开发集里只有 **2.6%** 的行含受损学名，每批 16 题平均不到半道。
- 把一半的题换成含受损学名的行（E5），P(修好 | 难词) 从 0.07 升到 **0.37**，整体奖励也略升（0.93 → 0.95）。
- **对 7b 的意义**：学名加权（w = 3）放大了"修对学名"的奖励，但如果训练数据里几乎没有这样的题，权重再大也没用，**题目选择和奖励设计要一起定**。代价是改变了训练分布，要在不过采样的同书内测试集上检查普通词有没有退化。这正是计划 6.4 里 w = 1 与 w = 3 对照、以及模块五高信号题库要回答的问题。

## 4. 带到 7b 的设置

| 设置 | 初始取值 | 理由 |
|---|---|---|
| 每组采样数 G | 8 | 玩具：T = 1 时信号为零的组从 G = 4 的 49% 降到 27%；TRL 默认也是 8（来自文档摘要） |
| 温度 | 1.0，先在目标小模型上测 `frac_reward_zero_std` | 太低信号少，太高格式乱 |
| 损失汇总 | `dapo`（TRL 默认） | 避免长行被摊薄 |
| KL β | 0，另跑一个小 β 的对照 | 主要靠奖励里的扣分防乱改 |
| 动态过滤 | 开启，并记录被过滤的比例 | 训练后期大量组全对 |
| 训练题 | 过采样含受损学名的行，另报不过采样的对照 | 学名行只占 2.6% |
| 必须记录 | 奖励、`frac_reward_zero_std`、KL、输出长度、各诊断字段 | 计划 7b |

## 5. 来源（已核对）

- GRPO：Shao 等，2024，*DeepSeekMath*，arXiv 2402.03300。
- Dr. GRPO：Liu 等，2025，*Understanding R1-Zero-Like Training: A Critical Perspective*，[arXiv 2503.20783](https://arxiv.org/abs/2503.20783)。去掉按长度和按标准差的归一化；指出 GRPO 会让错误回答变长。
- DAPO：Yu 等，2025，*DAPO: An Open-Source LLM Reinforcement Learning System at Scale*，[arXiv 2503.14476](https://arxiv.org/abs/2503.14476)。动态采样（过滤准确率为 0 或 1 的组）、token 级损失、Clip-Higher（ε 上下界分开；具体数值这次没读到原文，不写）、去掉 KL。
- Yue 等，2025，*Does Reinforcement Learning Really Incentivize Reasoning Capacity in LLMs Beyond the Base Model?*，[arXiv 2504.13837](https://arxiv.org/abs/2504.13837)。小 k 时 RL 模型 pass@k 更高，大 k 时基础模型更高；7c"学会了还是更稳定"要用到。
- TRL GRPOTrainer 文档：[huggingface.co/docs/trl/main/en/grpo_trainer](https://huggingface.co/docs/trl/main/en/grpo_trainer)。`frac_reward_zero_std`、β 默认 0 已读原文；`loss_type` 各选项、`scale_rewards` 默认值、`num_generations` 默认值来自文档摘要，开工 7b 时锁定版本后再核对。
