# 从文献到数据的管线在哪里丢失可靠性？下一笔资源应该投在哪里？

*决策备忘录，Gloria 审阅稿，2026-11-20。英文版见 `memo/MEMO.md`，两版内容一致。证据来自
BioEvidenceBench V1：在生物多样性遗产图书馆（BHL）的两本历史文献上做的试点（Butler 1907，鸟类；
Reeve 1849，贝类），外加 8 页植物学外部案例（PCAS 1898）。标 **[预注册]** 的结果来自冻结后的测试
运行（`FREEZE.json`，16 个锁定测试页，金标准在看到任何模型输出之前标完）；标 **[探索性]** 的结果
是解封之后才设计的（`DEVIATIONS.md`），要在新的测试集上复现才能算结论。给出区间的，都是按书
分别计算的 95% 按页 bootstrap 区间。*

**读者**：正在决定把下一笔钱或人力投到哪里的团队，目标是把历史生物多样性文献变成结构化、可信的
数据（学名、人名、地名、机构、日期）。

BioEvidenceBench 是对**有证据支撑的科学数据抽取**（evidence-grounded scientific data extraction）做的
系统级评估，不是 OCR 基准：OCR 只是它跟踪的管线中的一环（OCR 本身的打分 FineBooks 已经在做）。

## 问题不是"哪个 OCR、哪个 LLM 分数最高"

一条记录的可信程度，取决于从印刷页到数据库这一路上最薄弱的那一环。这个试点跟着一个提及走完每一
步，问三个问题：可靠性到底丢在哪里、丢了多少、补回来要花多少。

## 结论

在这两本书上（英文，1849 年和 1907 年印刷），**OCR 是第一个瓶颈，现代 OCR 便宜地解决了大部分；
之后限制可靠性的是实体解析和"什么算一条数据"的定义，而不是抽取。** 这**不**等于 OCR 投资已经可以
结束：其他语言、版式、印刷年代、表格、图版和手写记录的错误分布可能完全不同，这次试点没有测过。
下一笔资源应该投在：（1）按材料类型测量学名能否完整通过 OCR，过不了的地方重新 OCR；（2）实体解析，
用 LLM 关联器，配合由馆员负责的分类学口径；（3）把"抽什么"写成明确的范围说明；（4）基于抽样的审核。
**不该**花钱的地方是更大、更贵的抽取模型。

## 逐环节看可靠性丢在哪里

| 环节 | 测了什么 | 在这里丢了多少 | 能否补回、代价多大 |
|---|---|---|---|
| **1. 扫描页 → 文字（OCR）** | 在 BHL 旧 OCR、现代开源 OCR、专家转录三种文字上抽取 | **损失最大。** 值 F1：Reeve 0.64 → 0.98 → 0.98，Butler 0.60 → 0.95 → 0.98 **[预注册]**；163 个出错的金标准提及里 151 个与 OCR 相关（Gloria 的错误标注） | 在这两本书上可以，而且便宜。现代 OCR、保留原文引语的 LLM 读正（Butler 0.60 → 0.96）、直接读扫描图（0.96 / 0.98）都能补回大部分 **[探索性]**，但它们留下的证据不一样（见下一节）。补不回的：读起来通顺的 OCR 错误（把 `Linnæus` 读成 `Linnaeus`），后面任何一步都看不出来（读正后也只有 0.81 / 0.87） |
| **2. 文字 → 提及（抽取）** | LLM 对比规则基线；四个 Claude 模型 | 文字干净后损失很小：专家转录上 0.98；规则方法在学名上差很多（学名 0.64 / 0.54）**[预注册]**。换模型 F1 变化不超过 0.05；Haiku 成本约为 Opus 的 1/15 **[探索性]** | 已经解决。用够用的最便宜模型 |
| **3. 提及 → 证据（核查）** | 值由代码从原文切出；模型给的引语逐字核对 | **不降低准确率；它的价值在现有指标里看不出来。** 要求给引语后召回率变化在 −0.015 到 +0.007 之间 **[预注册]**。两组都没有出现无依据的值，因为两组的值都由代码从原文取出（切片或对齐）：这次比较的是两种核查方式，而不是"有核查"对"没有核查"，所以测不出减少。这**不**说明证据核查没有价值。它的价值在可追溯性和审核成本，准确率衡量不到（见下一节）。视觉模型画的框只有 67% / 40% 落在对的词上 **[探索性]** | 保留为设计要求：每个值带行号和原文引语，图像坐标从 OCR 词坐标来。下一轮用审核指标测它的价值：能追溯到原页的值占多少、每个值的审核时间、有证据和没证据时审核人能抓到多少错误 |
| **4. 提及 → 实体（实体解析）** | Butler 的学名关联到 GBIF | **文字干净后损失最大的一环。** 直接查 GBIF，34 个已正确抽出的学名里丢了 14 个，而关联之前丢 0 个（差值 0.41 [0.25, 0.60]）**[预注册]** | 大部分能补回。LLM 关联器（名字 + 上下文 → 今天的接受名 → GBIF）把关联召回率从 0.59 提到 0.91；剩下的是分类学判断（采用哪个物种概念、哪份名录）**[探索性]**。这一环换模型有影响（Opus 0.91，Haiku 0.76） |
| **5. 什么算一条数据（范围定义）** | 标注一致性；PCAS 裁决；整本书抽检 | 两名标注者完全一致 0.90，重叠一致 0.95。PCAS 上只是统一五条边界约定（称呼、连写地名），F1 就从 0.83 到 0.94，模型没有任何改动。整本书试跑中 16% 的提及落在指南从未定义过的索引页上；把索引页定为范围外之后，需要审核的提及（模型不一致或检查未过）从 1,404 条降到 555 条 **[探索性]** | 能，而且便宜：写一份范围说明（索引页、命名人、泛指俗名），再加一位裁决人。很多看起来是"模型错误"的，其实是范围没定义 |
| **6. 审核（人工或自动）** | 模型一致作为免审信号；便宜的自动检查；整本书抽检 | 一致不等于正确：旧 OCR 上被标为"两模型一致"的提及里，Butler 有 50 个、Reeve 有 75 个是错的 **[预注册]**。现代 OCR 上，样本以外抽检的 25 个 Opus 输出全对，第二个模型找出了 Opus 漏掉的真提及（14 个里 10 个）**[探索性]** | 按文字质量分流：旧 OCR 上两条机械检查只看 25% 的输出就能抓到 55% 的错误；干净文字上做随机抽样质检（每条约 30 秒），用第二个模型找漏，绝不因为模型一致就跳过审核 |

## 准确率相同，不等于证据相同

绕过糟糕 OCR 的三条路线，值 F1 接近，但产出的证据并不等价，可审计的程度也不同。审核人能核对什么、
要花多少工夫，差别很大：

| 路线 | 值 F1（Butler / Reeve） | 值从哪里来 | 文字证据（第 2 层） | 图像证据（第 3 层） | 审核人要做什么 |
|---|---|---|---|---|---|
| 现代 OCR + 带证据的抽取（G1） | 0.95 / 0.98 **[预注册]** | 代码从 OCR 文字里切出，从不改写 | 行号 + 原文引语，由代码核对 | dots.mocr 给不了（Markdown 输出，没有坐标）；需要带词坐标的 OCR 输出 | 切出来的值可以信；只在要排查 OCR 读错时打开扫描页（抽检的 25 个值里没有读错） |
| 旧 OCR + LLM 读正（G2） | 0.96 / 0.91 **[探索性]** | 模型给的读法；旧 OCR 上约 30% 的值和引用的 OCR 原文不同（每条都标了 `repaired`） | 对旧 OCR 原文的引语可以核对；读正后的值不能 | 可以通过旧 OCR 的 hOCR 词坐标实现（未演示） | 每条读正过的值都要对照扫描页核查：92% 是对的，也就是约 12 条里有 1 条是模型自信的误读 |
| 只看扫描图（V1） | 0.96 / 0.98 **[探索性]**，按值集合计分 | 模型的转录 | 没有 | 模型自己画的框：只有 67% / 40% 落在对的词上（V3） | 每个值都要人工在扫描页上找；框不能当作指针 |

还有两点要注意：只看图那一行用的是按值集合计分（页面上有相同文字就算对），分不出"值对但位置错"
和"值对且位置对"；视觉模型的转录和任何文字之间都没有可核对的联系。**选路线要同时看准确率和每个值
的审核成本，不能只看 F1。** 在证据重要的场合（数据要进 GBIF，或成为可引用的记录），这里只有"带词
坐标的现代 OCR + 引语核对的抽取"这条路线，能让每个值都机械地追溯回原页面。

## 建议：下一笔资源投在哪里

1. **继续投 OCR，但按材料类型用"学名是否完整保留"来验收。** 选 OCR 看小样本上有多少学名完整保留，
   不看整页错字率：22 个 OCR 版本里，整页错字率几乎预测不了抽取效果，学名保留率几乎完全预测得了
   （Spearman 0.95 / 1.00）。像这两本书这样的英文印刷文献，现代 OCR 已经够用；其他语言、版式、年代、
   表格、图版和手写材料，先做同样的测试再决定，它们的错误分布可能完全不同。优先选错误"看得出来"的
   OCR：读起来通顺的误读，下游无法修复。
2. **把实体解析当成独立的工作来投入。** LLM 关联器能补回大部分关联损失，而且调用量小（每个不同的
   名字一次）。剩下的需要馆员决定数据采用哪份名录、哪种物种概念，这是治理问题，不是工程问题。
3. **规模化之前先把范围写下来。** 索引页、合著命名人（`H. & A.`）、泛指俗名、地名边界，能让分数差到
   十个百分点。由一位裁决人一次定好，把不在范围内的过滤掉：抽检之后已决定排除 BHL 标为 Index 的页，按页面类型过滤，几乎不花成本。
4. **基于抽样审核，并附带证据。** 优先选能留下机器可核对记录的路线（切出来的值、原文引语、OCR 词
   坐标）；模型读正后的值和看图得到的转录，凡是改动过或没有锚点的，都需要人逐条看。每个值都保留行号
   和原文引语。旧 OCR 上用便宜的检查来分流；干净文字上用随机抽样估计质量，用第二个模型找漏。不要因为
   两个模型一致就跳过审核。
5. **不要买更大的抽取模型。** Haiku 5.5 抽完 682 页花了 $0.40、用时 7.5 分钟；Opus 5.5 花 $7.64，只高
   几个百分点。把差价花在第 2–4 条上。

## 对研究问题的回答

*改进 OCR 什么时候不再是主要瓶颈？* 在这两本书上，学名能完整通过 OCR 时就不再是：现代 OCR、LLM 读正
或直接读图，都能把抽取做到约 0.95。其他材料能否同样容易到达这一点，是一个开放问题，不是这次试点的
结论。不存在单一的整页错字率阈值，该看的是学名保留率。*之后限制可信数据的是什么？* 实体解析（文字
干净后测到的最大损失）、"什么算一条数据"的定义，以及任何一步都看不出来的错误（通顺的 OCR 误读）。
要求给证据没有改变现有的准确率指标，这说明这些指标没有衡量到证据的用途，而不是证据核查没有价值：
它把 F1 看似相同的路线区分开（只有从 OCR 文字中做引语核对的抽取，能让每个值都有一条机械可追溯的记录
回到原页面）；图像坐标必须来自 OCR 词坐标，而不是视觉模型。

## 这份结果说明不了什么

- 两本书（外加 8 页植物学）：只能给试点指方向，不是适用于整个 BHL 的规律。书和 OCR 质量相互混杂，
  所以结果按书分别报告。PCAS 案例在植物学上指向同一方向。
- 所有材料都是 1849–1907 年的英文印刷文本。其他语言（拉丁文为主的描述、德文、法文）、密集的表格和
  索引、图版说明、更早或破损的印刷品、手写的野外记录或标签，OCR 出错的方式可能不同；"OCR 不再是
  主要瓶颈"这个结论不能推广到它们。即使在这次材料里，Reeve 的索引表经现代 OCR 后也变成了 HTML 表格
  标记，这是版式带来的影响，这次没有计分。
- 探索性结果是在看过测试结果之后设计的，需要新的测试集。
- 这些书是公开的。读正和读图可能得益于模型预训练时见过它们；记忆探针没有发现模型记住了页面（看不出
  错的替换 29 次里一次都没被改回），但这不能证明完全没有。
- 金标准只有一名标注者；第二名标注者只标了 5 页。PCAS 的边界裁决是在看过模型输出之后做的，两个
  版本都报告。
- 实体解析只在鸟类上测过（34 个有金标准接受名的学名）。贝类学名（Reeve，56 个不同的名字）留到下一
  轮：手工建关联金标准要 2–3 小时，而预注册的问题已经在 Butler 上回答了。LLM 关联器的提升在同物异名
  更多的软体动物上是否成立，还没验证。
- 审核时间只来自 9 条计了时的抽检（中位数 30 秒），不是专门的审核时间研究。

## 成本

整个项目 API 花费约 $49（Claude 约 $42，Gemini 约 $7），包括四个 Claude 模型、682 页的整本书试跑和
植物学案例。每页每次的成本：抽取约 $0.0006（Haiku，批量）到 $0.011（Opus，批量）；LLM 读正约
$0.05，读图约 $0.04（Opus，同步）。真正的成本是人：标注 22 + 8 页、Butler 学名关联、错误标注，
以及 60 条抽检。
